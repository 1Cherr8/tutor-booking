
# Описание проекта Tutor Booking

## 1. Назначение проекта

**Tutor Booking** — веб-приложение для записи клиентов на индивидуальные занятия с репетитором.

Система позволяет обычному пользователю зарегистрироваться, авторизоваться, посмотреть доступные предметы и создать запись на занятие. Администратор может управлять предметами и просматривать записи всех пользователей.

В приложении предусмотрены две роли:

- `Client` — обычный пользователь;
- `Admin` — администратор.

### Страница авторизации

Пользователь может войти в существующий аккаунт или перейти к регистрации.

![Авторизация](images/login.png)

---

## 2. Архитектура и технологии

Проект построен по клиент-серверной архитектуре и состоит из трёх основных компонентов:

```text
Пользователь
     ↓
Frontend
React + Nginx
     ↓
Backend
FastAPI
     ↓
Database
PostgreSQL
```

### Frontend

Пользовательский интерфейс реализован с использованием:

- React;
- Vite;
- JavaScript;
- HTML;
- CSS;
- Nginx.

Frontend доступен по адресу:

```text
http://localhost:3000
```

### Backend

Серверная часть реализована на Python с использованием FastAPI.

Backend отвечает за:

- авторизацию;
- работу с пользователями;
- работу с предметами;
- работу с записями;
- взаимодействие с базой данных;
- проверку прав доступа.

Для просмотра REST API используется Swagger:

```text
http://localhost:8000/docs
```

### Swagger API

![Swagger API](images/swagger.png)

### Database

Для хранения данных используется PostgreSQL.

В базе данных хранятся:

- пользователи;
- предметы;
- записи на занятия.

Для взаимодействия backend с PostgreSQL используется SQLAlchemy.

---

## 3. Docker

Frontend, backend и база данных запускаются в отдельных Docker-контейнерах.

В проекте используются три основных сервиса:

```text
frontend
backend
db
```

Их конфигурация находится в файле:

```text
docker-compose.yml
```

Проект запускается командой:

```bash
docker compose up --build
```

### Запущенные Docker-контейнеры

![Docker](images/docker.png)

Использование Docker позволяет запускать всё приложение одной командой без отдельной настройки PostgreSQL, Python и Node.js на компьютере.

## 4. Бизнес-сущности и CRUD

По заданию в проекте реализованы две основные бизнес-сущности с полным набором CRUD-операций:

1. `Subject`;
2. `Booking`.

CRUD включает:

```text
CREATE
READ
UPDATE
DELETE
```

### Subject

`Subject` представляет предмет или услугу репетитора.

Например:

- Математика;
- Физика;
- Информатика.

Для `Subject` реализованы:

- **Create** — создание нового предмета;
- **Read** — просмотр списка предметов;
- **Update** — изменение предмета;
- **Delete** — удаление предмета.

Управление предметами доступно администратору.

### Booking

`Booking` представляет запись клиента на занятие.

Для `Booking` реализованы:

- **Create** — создание записи;
- **Read** — просмотр записей;
- **Update** — изменение записи;
- **Delete** — удаление записи.

Обычный пользователь работает со своими записями, а администратор может просматривать и изменять записи всех клиентов.

## 5. Авторизация и роли

В системе реализована авторизация пользователей.

Поддерживаются две роли:

```text
client
admin
```

Для авторизации используются JWT-токены.

После входа пользователь получает доступ к функциям в соответствии со своей ролью.

### Client

Клиент может:

- зарегистрироваться;
- авторизоваться;
- просматривать предметы;
- создавать записи;
- просматривать свои записи;
- изменять свои записи;
- удалять свои записи.

### Кабинет клиента

![Клиент](images/client.png)

### Admin

Администратор может:

- авторизоваться;
- добавлять предметы;
- изменять предметы;
- удалять предметы;
- просматривать все записи пользователей;
- изменять и удалять записи.

### Панель администратора

![Администратор](images/admin.png)

Права доступа проверяются на стороне backend, поэтому функции администратора недоступны обычному клиенту.

```text
http://localhost:3000
```

```text
http://localhost:8000/docs
```
